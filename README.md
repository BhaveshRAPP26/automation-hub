# Analytics Enablement Automation Hub

A collection of **Analytics Enablement automations** for simplifying repetitive QA, tracking validation, data extraction, and analytics implementation tasks.

The Automation Hub provides a single interface for running multiple automation tools without needing to manually execute individual Python scripts.

---

## 🚀 Quick Start

**Not sure which automation to use?**

| I want to... | Use |
|---|---|
| Check URLs for UTM syntax issues | **Checkem** |
| Break down GA4 requests into parameters | **GA4 Request Parameter Breakdown** |
| Find the GTM snippet ID on multiple websites | **GTM Snippet Identifier** |
| Automatically click page elements and capture GA4 requests | **GTM QA Automation** |
| Convert GA4 requests from JSON into text | **JSON to Text** |
| Find the OneTrust snippet ID on multiple websites | **OneTrust Modal Identifier** |
| Test OneTrust consent and whether tags fire correctly | **OneTrust QA** |

# 📦 Automations

## 1. Checkem

**UTM & URL Syntax Validator**

Check whether URLs containing UTM parameters have potential syntax issues.

### Input

A list of URLs containing UTM parameters.

### What it does

- Reads the supplied URLs.
- Checks the URL and UTM structure.
- Identifies potential syntax issues.

### Output

A validation result showing which URLs have issues.

### Best for

- Campaign URL QA
- UTM validation
- Bulk link checking

---

## 2. GA4 Request Parameter Breakdown

**GA4 Request Analyzer**

Break down GA4 network requests into their individual parameters and group them by event name.

### Input

A list of GA4 requests.

### What it does

- Reads each GA4 request.
- Extracts its parameters.
- Identifies the event name.
- Groups requests/parameters by event.
- Presents the results in a structured format.

### Output

A parameter breakdown that can also be downloaded as an **Excel file**.

### Best for

- GA4 implementation QA
- Event parameter analysis
- Comparing GA4 requests
- Identifying missing/unexpected parameters

### Workflow

This automation can also be used with **JSON to Text**:

```text
GTM QA Automation
        ↓
      JSON
        ↓
  JSON to Text
        ↓
      TXT
        ↓
GA4 Request Parameter Breakdown
        ↓
     Excel
```

## 3. GTM Snippet Identifier

**GTM Container ID Finder**

Identify the Google Tag Manager snippet/container ID implemented on websites.

> ⚠️ **Commercial Lubes specific**

### Input

One or more website URLs.

### What it does

- Visits/retrieves the supplied website HTML.
- Searches the page for the GTM implementation.
- Extracts the GTM snippet/container ID.

### Output

The GTM snippet/container ID found for each URL.

### Best for

- Bulk GTM implementation checks
- Website inventories
- Confirming GTM container implementation

---

## 4. GTM QA Automation

**Automated Element Interaction & GA4 Request Capture**

Automatically interact with HTML elements on a webpage and capture the GA4 network requests generated by those interactions.

### Input

A `.txt` file containing:

- HTML element IDs to interact with
- The page URL encoded in the filename

### Example

```text
example_com_products_page_ids.txt
```

The Hub uses the filename to reconstruct the target page URL.

The file itself contains the HTML IDs to test:

```text
link_product_1
link_product_2
link_product_3
link_product_4
```

### What it does

1. Reconstructs the page URL.
2. Opens the page.
3. Reads each HTML ID from the file.
4. Finds the corresponding element.
5. Simulates a click.
6. Captures the resulting GA4 network request.
7. Logs the result.
8. Continues through the remaining IDs.

### Output

Results are displayed in the Hub and can be downloaded as a **JSON file**.

### Best for

- Automated GTM/GA4 QA
- Testing large numbers of page elements
- Capturing GA4 requests generated by interactions
- Reducing repetitive manual QA

### ⚠️ Important

The HTML IDs must correspond to elements that can be found on the target page.

Website changes such as changed IDs, page structure, JavaScript behavior, or tracking implementation may affect the results.

## 5. JSON to Text

**GA4 Request Format Converter**

Extract GA4 requests from a JSON file and convert them into a text file.

### Input

A JSON file containing GA4 request information.

The JSON can, for example, be generated by **GTM QA Automation**.

### What it does

- Reads the JSON file.
- Extracts the GA4 requests.
- Places each request on a separate line.

### Output

A `.txt` file:

```text
GA4 request 1
GA4 request 2
GA4 request 3
...
```

### Best for

Preparing GA4 requests for use with:

**GA4 Request Parameter Breakdown**

### Typical Workflow

```text
GTM QA Automation
        ↓
      JSON
        ↓
   JSON to Text
        ↓
      TXT
        ↓
GA4 Request Parameter Breakdown
```

**OneTrust Snippet ID Finder**

Identify the OneTrust snippet ID implemented on websites.

> ⚠️ **Project specific**

### Input

One or more website URLs.

### What it does

- Retrieves/scrapes the website HTML.
- Searches for the OneTrust implementation.
- Extracts the relevant OneTrust snippet ID.

### Output

The OneTrust snippet ID found for each URL.

### Best for

---

## 7. OneTrust QA

**Consent & Tag-Firing QA**

Automate a OneTrust consent scenario and check whether analytics tags/requests behave as expected when consent changes.

### Input

A website/page URL.

### What it does

The automation:

1. Opens the website.
2. Checks the current consent state.
3. Reads the relevant consent value.
4. Changes the consent state.
5. Monitors tracking/network activity.
6. Checks whether relevant tags or requests fire.
7. Records the observed behavior.

### Output

The Hub displays the observed:

- Consent state
- Consent changes
- Tracking behavior
- Tag/network activity
- QA results

### Best for

- OneTrust QA
- Consent validation
- Analytics tag-firing validation
- Consent-management troubleshooting

### ⚠️ Important

The expected result depends on the website's consent-management and analytics implementation. A failed check should therefore be investigated rather than automatically treated as a confirmed implementation defect.

# 💻 Running the Hub

## Prerequisites

Install Python and the required dependencies.

```bash
pip install -r requirements.txt
```

If Playwright is used:

```bash
playwright install
```

## Start the application

Run the Streamlit application:

```bash
streamlit run mainmenu.py
```

The application will open in the browser.

# ➕ Adding a New Automation

Before developing a new automation, consider:

- Does the process happen frequently?
- Is it repetitive?
- Does it require significant manual effort?
- Can the process be standardized?
- Does an existing Hub automation already solve the problem?
- Can the solution be reused across projects?

New automations should ideally include:

- A clear user-facing description.
- Defined input requirements.
- Defined output.
- Appropriate error handling.
- Testing.
- Documentation.
- A designated owner.

# ⚠️ Important Usage Notes

### Website-dependent automations

Automations that interact with websites depend on the current implementation of those websites.

Changes to:

- HTML
- Element IDs
- JavaScript
- GTM
- GA4
- OneTrust
- Network requests

may affect results.

### Business-unit / project-specific automations

Some automations are not intended for general use:

| Automation | Scope |
|---|---|
| GTM Snippet Identifier | Commercial Lubes |
| OneTrust Modal Identifier | Specific project |

Check the automation description before using these tools for other projects or business units.

### Automation output

Automation results should be **reviewed and interpreted by the user**. Automated results are intended to support QA and analysis, not replace appropriate human validation.
